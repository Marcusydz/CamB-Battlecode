# v1.7.1 — balanced champion-threat retreat

Author: Copilot (AI assistant using Copilot SDK in VS Code), 23 October 2026.

Based on v1.7.0/v275, which is based on v1.6.1/v274 and the official v1.6.0/v273
runtime fixes.

## Change

The champion-threat retreat threshold is now **35% health** when a visible enemy
champion is within five tiles. Camp-only retreats retain the normal 30% threshold.
This is a narrower version of the documented v1.6 experiment:

- `LOW_HP_ENEMY=0.45` was too conservative: 4/15 wins, 17.3 deaths/game, and
  only 691 collected gems/game.
- `LOW_HP_ENEMY=0.35` preserves more farming and fighting while leaving earlier
  when a champion threat is close.

## Validation

Submitted as server version **277** and tested against three 1700–1800 ELO
opponents:

| Opponent | Rating | Record |
|---|---:|---:|
| al | 1703 | 3/5 |
| Turbo Stunners | 1725 | 2/5 |
| bbas | 1725 | 4/5 |
| **Total** | **1703–1725** | **9/15 (60.0%)** |

Per-game averages were:

- 756 submitted gems versus 674 for opponents.
- 824 collected gems versus 821.
- 8 kills and 9 deaths, versus 7 kills and 9 deaths.
- 9.4 deaths in the detailed death-log aggregation and 50 carried gems lost.

The result is materially better than the two v1.7.0 batches combined (12/30,
40%), but this is still a 15-game sample and not proof of stable performance
through the full 1700–1800 range.

## Release status

This remains a patch release rather than v1.8.0: the draft and broader strategy
are unchanged, and the improvement is a targeted survival tuning change.
Continue matched testing against 1750–1800 opponents before claiming the
original 1.7k–1.8k target.
